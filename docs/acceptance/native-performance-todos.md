## 定向测量

组件基准每项运行五对，顺序为 AB、BA、AB、BA、AB。时间列为每次操作的独立中位数，降幅为五对各自时间降幅的中位数。一次窄串操作包含正反两次查找。ABC 使用运行时的区间读取入口。

| 输入 | 基线中位数 | 候选中位数 | 配对耗时降幅 | 每次分配工作量 |
| --- | ---: | ---: | ---: | --- |
| 64 KiB 窄串，无匹配 | 447.6 µs | 128.1 µs | 76.8% | 两侧均 0 次堆分配 |
| 64 KiB 尾部 NUL | 34.63 µs | 1.70 µs | 95.7% | 两侧均 0 次堆分配 |
| 1,024 个字符串的 ABC | 46.30 µs | 5.28 µs | 89.1% | 1,033 → 9 次，98,208 → 32,704 字节 |
| 约 1 MiB 的 ZWS 正文 | 8.41 ms | 7.44 ms | 12.8% | 95 → 93 次，6,316,322 → 5,266,829 字节 |

下表来自两个冻结的 Linux `dist` 二进制。glibc 探针在主线程按指定函数的调用栈累计申请与重分配，取同一场景 32 帧和 8 帧两次运行的差值，表示额外 24 个测量帧的分配工作量。宽范围的 `Player::run_frame` 包含该场景的其他帧内工作。此探针的耗时不计入性能对照。

| 场景 / 采样函数 | 分配次数，基线 → 候选 | 申请字节，基线 → 候选 |
| --- | ---: | ---: |
| 定时器，`Timers::update_timers` | 240 → 0 | 11,520 → 0 |
| 闭包作用域，`ScopeChain::chain` | 14,400 → 9,600 | 2,956,800 → 1,344,000 |
| SWF5 同目标调用，`Avm1Function::exec` | 90,000 → 84,001 | 10,716,000 → 10,476,040 |
| XML 克隆自有属性，`xml_node::clone_node` | 16,800 → 15,120 | 2,486,400 → 2,325,120 |
| HTML 属性，`FormatSpans::from_html` | 13,440 → 12,000 | 1,032,720 → 1,024,320 |
| FTE 拆分，`Player::run_frame` | 61,536 → 48,096 | 4,986,864 → 3,358,128 |
| 稀疏绑定方法，`Player::run_frame` | 17,232 → 18,144 | 1,789,872 → 1,601,904 |
| 多深度跳帧，`MovieClip::run_goto` | 360 → 624 | 3,752,832 → 2,839,104 |

稀疏绑定和多深度跳帧都减少了申请字节，并且增加了分配次数。拖动场景的 16 次 `update_drag` 在基线上分别调用 16 次 X 和 16 次 Y 设置器。候选对这两个独立设置器的调用均为 0，拖动位置序列一致。曲线场景在两个版本都执行了 20 次描边命中检测，进入三次方程求解的次数为 20 → 0。GPU 读回测试同时检查像素，局部混合格式的恒等滤镜只提交一次滤镜 pass，最多处理两个 pass 像素。
